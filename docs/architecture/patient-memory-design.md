# 患者长期记忆与对话归档

设计参考：[用户提供的博客正文](https://blog.csdn.net/Anmory/article/details/170035015)。实现覆盖显式写入、每轮结束抽取、证据校验、时效失效、冲突审计和短摘要注入。

## 两种数据各自做什么

### 长期记忆

长期记忆不进向量归档表。SQLite 的 `patient_long_term_memories` 保存患者编号、类别、内容、重要度、置信度、原话证据、来源、有效时间、过期时间、保护标记、状态、替代关系、冲突关系、最近使用时间和访问次数。

每轮运行前会做一次维护，并把最新的短摘要放进主 Agent 和专科 Agent 的系统提示词：

1. 已到 `expires_at` 的条目改为 `expired`，后续不进入提示词。
2. 按类别设置半衰期：过敏、药物、禁忌 3650 天；重要事件/事实 1095 天；偏好、沟通、服务需求 365 天；普通情节 180 天。权重为 `importance × 20 × confidence × 2^(-ageDays / halfLifeDays)`，上限 100。
3. 权重低于 12 的普通条目标成 `stale`，留在数据库供个人中心审计；保护记忆不会因为权重低而变成陈旧。
4. 保护记忆优先，再按权重排序，写进约 900 字符的摘要并保存到 `patient_long_term_profiles`。摘要带类别、权重和生效日期。
5. 主 Agent 和被选中的专科 Agent 每次建图时都会收到这段摘要。没有长期记忆时，也会明确注入“暂无已确认的长期偏好或服务安排”。

用户明确要求记住时，`save_patient_memory` 立即写入，重要度 1–5，并可设过期时间。每轮完成后，服务将用户原话放入 SQLite 持久任务队列；后台 worker 按 `PATIENT_MEMORY_EXTRACTION_INTERVAL_SECONDS` 处理，不阻塞当前回复。服务重启时会恢复处理中断的任务，失败任务按退避间隔重试，最多 5 次。

抽取模型只能读取当轮用户原话和该患者当前有效记忆。普通事实必须提供原话中的连续引用，引用校验失败就跳过；显式记忆意图由模型按语义识别，优先写入。助手回复、工具结果和模型推断不作为事实来源。过敏、药物和禁忌作为用户自述保留并标记保护属性，不代表医疗人员已核实。

抽取使用 DeepSeek JSON Output，再由 Pydantic 校验结果字段；不使用 LangChain 的强制函数调用格式，因为 DeepSeek Thinking 模式不接受指定 `tool_choice`。

用户明确纠正旧记忆时，旧版本保留为 `superseded` 并记录替代关系；新旧关系无法判断时，冲突双方标成 `conflicted`，都不进摘要。过期、陈旧、冲突、替代条目都不会被物理删除。

用户明确关闭记忆或要求忘记时，服务先在记忆数据库保存关闭状态和持久删除任务，当前请求立即停止读取、归档和抽取记忆。后台清理线程等该患者正在运行的 Agent 请求及会话落盘结束后，按患者前缀删除 LangGraph checkpoint，再删除会话目录和记忆数据。删除任务完成前，该患者的新 Agent 请求暂时返回冲突响应，避免新数据混进待清理范围；清理失败会保留任务并退避重试，服务重启后会恢复中断任务。记忆保持关闭，只有请求明确带 `memoryConsent=true` 才重新开启。

### 对话归档

用户原话和助手回复分别写入 `patient_memory_vectors` 的 `archive` 类别，用 BGE Small 中文模型生成 512 维向量。每轮开始时，只在同一患者的 `archive` 中做余弦相似度检索，主 Agent取前 4 条；需要更多历史时，`search_patient_history` 可再取前 5 条。归档内容不是当前事实，模型必须结合时间和来源判断。

每次真实检索会记录查询文本、会话编号、命中内容、来源和分数到同一 SQLite 文件的 `patient_memory_retrievals`。个人中心展示长期记忆摘要、全部记忆状态和最近 100 次实际召回。

召回会先多取候选再去重：忽略空白差异的重复原文只保留最相关的一条；用户问句会合并只差口语虚词“的”的版本；同一报告编号下，向量相似度很高、数值和异常/阴阳性等风险词一致的助手答复也只保留一条。报告编号、数值或风险词不同的内容继续分别保留。原始对话归档不删除，去重只影响发给模型的召回结果。

## 表和文件位置

| 内容 | 存储位置 |
|---|---|
| 长期记忆条目、摘要、状态和权重 | `AGENT_STORAGE_PATH/patient-memory-vectors.sqlite3` 的 `patient_long_term_memories`、`patient_long_term_profiles` |
| 每轮定时抽取任务 | 同文件的 `patient_memory_extraction_jobs` |
| 向量化的对话归档 | 同文件的 sqlite-vec 表 `patient_memory_vectors`，仅 `kind=archive` 参与历史向量检索 |
| 召回审计 | 同文件的 `patient_memory_retrievals` |
| 原始会话和图 checkpoint | `patient-sessions.sqlite3`、`patient-checkpoints.sqlite3` |

患者要求删除时，后台任务会清理以上三类存储中的对应患者数据；HTTP 请求不会等待清理结束。此流程删除 SQLite 中对应的逻辑记录。

## 当前边界

后台抽取只处理用户原话，不会总结整段对话，也不自动抽取症状、报告片段或助手给出的医疗结论。对话归档当前用向量相似度，不包含 BM25、图扩展或混合重排。
